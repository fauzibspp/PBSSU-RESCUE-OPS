## Authority, evidence and audit baseline

The approved Q-01/Q-02 role matrix remains unchanged. G-04/G-06/G-07 mappings below are existing policy, not proposed new grants: G-06 `setAssignments` is modeled for Control Room Operator and Incident Commander; G-07 `createMovement` for Operator, Commander and Field Responder with TENANT/ASSIGNED restrictions. They remain contract references only until exact implementation scope is authorized. Platform Super Admin receives no tenant operational access. Field Responder access remains assignment-scoped and fail-closed until valid assignment evidence exists. Organization Admin and Auditor receive no write authority by implication.

For any future command, derive actor, tenant and role from trusted authenticated context. Candidate evidence includes the selected tenant, actor membership, incident and resource IDs, base version, command, before/after state, reason where approved, occurrence time, server receipt time, outcome and correlation/idempotency data only if the approved schema supports it. Never place free-text sensitive operational data in generic logs or unrestricted event payloads. These are design requirements to be reconciled with the frozen schemas, not new audit columns approved here.

No external dispatch message or official agency acknowledgement is represented. No automatic assignment, release, replacement, lifecycle transition or notification is permitted. Q02-4's human internal assignment prerequisite and Q02-6 vehicle eligibility remain approved constraints; details beyond them require the decisions above.
